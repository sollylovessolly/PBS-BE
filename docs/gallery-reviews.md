# Gallery albums and customer reviews

All paths below are relative to the existing `/api` prefix. JSON list responses use
`{ data, pagination: { page, limit, total, totalPages } }`. Admin routes require the
existing bearer access token.

## Routes

Public gallery:

- `GET /gallery/albums?page=1&limit=12`
- `GET /gallery/albums/:slug`
- `GET /gallery/featured?limit=12`
- `GET /gallery/media/:photoId/:variant`, where `variant` is `full` or `thumb`

Admin gallery:

- `GET /admin/gallery/albums?page=1&limit=20`
- `GET /admin/gallery/albums/:id`
- `POST /admin/gallery/uploads` as multipart fields `file` and UUID `requestKey`
- `POST /admin/gallery/albums`
- `PATCH /admin/gallery/albums/:id`
- `DELETE /admin/gallery/albums/:id` with `{ "expectedVersion": 1 }`
- `POST /admin/gallery/cleanup-orphans` for an authenticated manual cleanup run

Public reviews:

- `GET /reviews?page=1&limit=12`
- `POST /reviews` as multipart fields `displayName`, `rating`, `text`, `phone`,
  optional `orderNumber`, literal `publicationConsent=true`,
  `consentVersion=review-publication-v1`, UUID `requestKey`, and zero to three
  repeated `photos` fields
- `GET /reviews/media/:photoId/:variant`, where `variant` is `full` or `thumb`

Admin reviews:

- `GET /admin/reviews?status=PENDING&page=1&limit=20`
- `PATCH /admin/reviews/:id`
- `DELETE /admin/reviews/:id` with `{ "expectedVersion": 1 }`

The detailed JSON request and response schemas are exposed in Swagger at
`/api/docs`. Existing global validation rejects unknown fields.

## Media and privacy

- JPEG, PNG and WebP files are decoded with Sharp. Metadata is stripped, EXIF
  orientation is applied, images are bounded to 40 megapixels, and full/thumbnail
  derivatives are produced without upscaling.
- Gallery uploads are limited to 10 MiB. Review photos are limited to 5 MiB each
  and three files per review.
- Storage keys are generated by the server under separate `gallery/` and
  `reviews/` prefixes. Order-production assets are never reused.
- Draft, pending and rejected media requires a signed browser URL. Its token
  expires after 15 minutes and responses are `private, no-store`.
- Public media is checked against current publication and consent state on every
  request. It has a 60-second browser/cache lifetime, so removal can have a
  bounded residual cache window of up to 60 seconds.
- Unattached gallery uploads expire after 24 hours. An in-process hourly task and
  the manual cleanup endpoint enqueue deletion. Physical deletion uses a durable
  database retry queue, reference-checks every key, and never deletes order files.
- Pending review retention is intentionally an owner policy: pending reviews are
  retained until the owner publishes, rejects or deletes them. No automatic
  retention period is promised.

## Configuration

In addition to the existing database, JWT, public API URL and Supabase storage
settings, these optional variables control rate limits and cleanup cadence:

```dotenv
GALLERY_UPLOAD_RATE_LIMIT_PER_MINUTE=20
REVIEW_SUBMISSION_RATE_LIMIT_PER_MINUTE=5
GALLERY_ORPHAN_CLEANUP_INTERVAL_MS=3600000
```

`PUBLIC_API_URL` must be the externally reachable HTTPS backend origin in
production so returned media URLs are usable by the browser. Keep the Supabase
bucket private; the backend performs controlled downloads.

The cleanup timer only runs while the application process is awake. On a sleeping
hosting plan, call the authenticated cleanup endpoint from a trusted scheduled job
or move the same cleanup operation to the host's scheduler.

## Release order

1. Back up the database and review the additive migration
   `20260923090000_add_gallery_and_reviews`.
2. Configure the environment variables on the host without committing secrets.
3. Run `npx prisma migrate deploy` during the release.
4. Deploy the application, then confirm `/api/health` and `/api/docs`.
5. Test an authenticated draft upload and a pending review before publishing any
   real customer content.

No production migration or deployment is performed by this implementation.
